# Code of Conduct

## Our Commitment

HexSpindle is committed to providing a respectful, professional, and welcoming environment for everyone participating in the project.

Contributors, maintainers, users, and other community members are expected to interact constructively and respectfully.

## Expected Behavior

Examples of positive behavior include:

- Treating others with respect and professionalism
- Giving and receiving constructive technical feedback
- Focusing discussions on ideas, code, and project outcomes
- Respecting differing experience levels and perspectives
- Being patient when helping other contributors or users
- Accepting reasonable maintainer decisions and review feedback
- Taking responsibility for mistakes and correcting them

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, intimidation, or personal attacks
- Discriminatory or derogatory comments
- Threats or encouragement of violence
- Deliberate disruption of project discussions
- Publishing another person's private information without permission
- Repeated unwanted contact
- Spam, trolling, or intentionally inflammatory behavior
- Abuse of issue trackers, pull requests, discussions, or other project communication channels
- Any other conduct that would reasonably be considered inappropriate in a   professional open-source project

## Technical Disagreements

Technical disagreement is normal and welcome.

Discussions should focus on the technical merits of an idea or implementation rather than the person proposing it. Maintainers may close, moderate, or redirect discussions that become repetitive, hostile, or unproductive.

## Scope

This Code of Conduct applies to participation in HexSpindle project spaces, including:

- GitHub issues
- Pull requests
- Code reviews
- Discussions
- Project documentation
- Other official HexSpindle communication channels

It also applies when someone is representing the HexSpindle project in a public capacity.

## Enforcement

Project maintainers are responsible for interpreting and enforcing this Code of Conduct.

Maintainers may remove, edit, or reject comments, commits, issues, pull requests, or other contributions that violate these standards.

Depending on the severity and circumstances, responses may include:

1. A private or public warning
2. Removal of inappropriate content
3. Temporary restrictions on participation
4. Permanent removal from project spaces

## Reporting Conduct Issues

Conduct concerns should be reported privately to the project maintainers rather than discussed publicly.

Reports will be reviewed as reasonably and confidentially as possible.

Security vulnerabilities should instead be reported according to the
[Security Policy](SECURITY.md).
